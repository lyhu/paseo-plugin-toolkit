# 会话列表、智能命名与归档新建 PRD

> 状态：右侧入口更新为工作区会话列表；智能命名与归档新建继续后台执行。验收边界见[验收记录](session-title-acceptance.md)。
> 日期：2026-10-26
> 主规格：[Paseo Toolkit PRD](prd.md#35-会话智能命名与收尾总结)
> 范围：自动业务命名、手动命名摘要，以及 `/clear` 前的收尾总结。当前交付智能命名与原生归档新建联动能力。

## 1. 目标与边界

让会话标题准确表达业务对象、主要目标或待解决的问题，便于在会话列表与历史中识别。早期自动调整，后期保持稳定；长会话由用户主动总结并重新命名；收尾时立即切换新草稿，旧会话成果由后台总结保存。

总结、话题判断和标题生成统一复用 Toolkit 共用 AI 模型，不另建模型配置或调用当前编码 Agent。当前配置为 Host 默认模型，工作区可覆盖；沿用工作区覆盖优先、否则 Host 默认的规则。这里的“全局”指会话所在 Host 的 Toolkit 模型配置，不代表自动跨 Host 共享凭据。

摘要仅用于该会话的理解、命名与收尾，不自动加入个人记忆，也不自动发送到后续会话。首版不加入自动长期记忆、跨会话聚类或新会话上下文注入。

### 1.1 最新交互要求（2026-10-26）

- 四字入口名称统一为「智能命名」，表达会话标题自动生成；取消顶部「自动总结」按钮。
- `/session-title` 静默总结并自动设置标题，替代此前的预览、确认后应用流程。摘要与任务信息保存在 Host，右侧不再展示命名调试页。
- 原右侧「智能命名」调试页改为「会话列表」，每个 workspace 只保留一个 tab；列表展示全部会话及时间、轮次，提供状态筛选，双击打开，标题后的「更多」下拉菜单触发智能命名。
- 工作台侧栏移除工作区下的会话列表及显示/隐藏开关，旧开关值不再生效。
- 「总结归档」改名为「归档新建」，仍放在「吸顶提问」旁。最新要求替代等待命名及手动发送流程：点击后立即提交原生 `/clear`，后台静默总结和生成标题。
- 前台只等待任务意图可靠保存的短 RPC，不等待模型、历史读取或标题写回。归档和新草稿均由宿主原生命令执行。
- 会话列表筛选与刷新同排，筛选位于刷新左侧；移除操作说明。会话行增加 hover 高亮，标题支持人工改名、复制和确认后永久删除，删除同时清理 Provider 原始历史。

## 2. 自动命名

### 2.1 触发和轮次

| 时机               | 行为                           |
| ------------------ | ------------------------------ |
| 第 1 轮正常完成    | 总结当前目标，生成首个业务标题 |
| 第 2～5 轮正常完成 | 更新摘要，判断是否需要调整标题 |
| 第 6 轮起          | 不再自动调用模型或改名         |
| 手动总结或收尾总结 | 不受前 5 轮限制                |

一轮以用户请求及其对应的完整助手执行为单位。工具调用、进度消息、权限问答和自动续跑不单独增加产品轮次，不能直接把每个 hook 当作一轮。失败、取消不触发分析；重试正常完成后按同一请求计入。自动化消息不得伪装成用户新请求增加轮数。

轮次从会话开始累计，重载、重启、重新打开会话不重置；存量会话结合可读取历史恢复。无法可靠恢复轮次时停止自动命名，提供手动总结入口。实现前须验证各 Provider 的消息边界、重试与续跑行为。

Toolkit 会话列表功能默认开启，包含标题自动生成、右侧会话列表和归档新建。自动命名默认开启，前 5 轮有效结果自动应用，用户可在设置中关闭。只对服务观察到创建的会话自动命名；存量会话统一使用手动命令。公共历史缺少完整的请求来源与失败/重试边界，多个未处理提问或历史 epoch 变化时暂停轮次自动命名，不推测轮数。新会话初始标题为空或等于 Paseo 的首行提示词临时标题时可自动命名；其余初始标题按人工标题保护。SDK 尚无标题来源字段，无法区分与临时标题完全相同的显式自定义初始标题。

### 2.2 话题变化规则

- 同一需求的细化、补充约束，以及从方案进入开发、测试，不视为换题。
- 主要业务目标变化、用户纠正此前理解，或原标题已明显不准确时，重新生成标题。
- 短暂支线、措辞变化或证据不足时保留原标题；不为了每轮都“有变化”而改名。
- 判断同时参考当前摘要、既有标题和新增对话，不能只根据最后一条消息。
- 一次模型请求返回摘要、是否改名、判断原因和推荐标题；程序校验后再写回。

自动摘要保存最新版本及历次处理记录，不在每轮聊天流中插入总结消息。手动命令生成用于命名的简短摘要，后台保存摘要，右侧会话列表只展示会话信息。

### 2.3 标题规范及人工保护

- 业务标题优先采用“业务对象＋目标/问题”，如“修复会员续费后的权益同步”。避免“继续讨论”“修改代码”等无法识别业务的标题。
- 默认最多 30 个用户可见字符，可配置为正整数，并受宿主支持的标题长度约束。中文、字母、数字、标点与空格均计入；组合字符和 emoji 不从中间拆开。
- 跟随会话主要语言，保留必要产品名、业务术语，不增加无意义引号、换行或前缀。
- 超长优先要求模型压缩一次；仍不合法则保留原标题并记录失败，不直接截断关键业务含义。
- 长度限制只约束本功能生成的标题，不裁剪用户手写标题。
- 用户手动改名后停止该会话的自动覆盖；用户显式执行 `/session-title` 时可重新生成并自动设置标题；若生成期间人工再次改名，则放弃旧结果。
- 对启用前已有的非空标题，无法确认来源时按人工标题保护；自动写回前再次核对标题，避免覆盖用户在模型请求期间的修改。

## 3. 手动命令 `/session-title`

推荐命令为 `/session-title`，含义为“后台总结当前会话并自动设置业务标题”，不是只改一个名字。注册前检查命令冲突；不使用宿主保留的 `/clear`、`/new`，也不覆盖 Provider 命令。

交互流程：

1. 固定命令触发时的历史边界，在后台开始处理；不打开面板、不弹出确认、不向聊天流插入总结。命令文本不发送给当前编码 Agent，也不增加产品轮次。
2. 分页读取截至边界的用户与助手文本，提取目标、关键决策、已完成事项、待办和话题演变。排除工具原始输出、思考过程与插件自身总结行；附件仅处理可读取的文本，不宣称理解未读取的内容。
3. 用户消息不超过 20 条且序列化命名素材不超过 10,000 字符时保留全文；超过任一阈值后优先使用用户问题：最多保留开头 2 条、中间均匀采样 6 条、最近 8 条，以及最近 2 条助手文本，按原始顺序提供。单条用户文本最多保留 600 字符、助手文本最多 400 字符，保留首尾并标记省略；按 JSON 序列化长度继续缩减单条预算，确保素材总量不超过 10,000 字符。没有用户文本时对助手文本做同样的有界采样。
   - 单次推理生成命名摘要、话题判断与标题，提示模型将摘要控制在 800 字符内、原因 160 字符内，输出额度最多 1500 tokens。主请求超时 30 秒；仅标题不合规时再修正一次，最多 15 秒，模型等待总预算 45 秒。超时和无效响应不自动重试。
   - 这是用于命名的摘要，替代此前的全量串行分段总结。采样／裁剪时在保存的摘要前标注选取消息数和裁剪数，不宣称完整覆盖历史；完整分页历史仍用于指纹与写回前的一致性检查。
4. 成功后自动写回生成标题，并持久保存摘要、覆盖范围、原有标题和改名原因，无需再次确认。后台任务失败不弹窗，错误保留在 Host 后台记录。
5. 写回前核对会话身份、历史指纹和当前标题；内容或人工标题在生成期间变化时放弃旧结果，在后台记录原因。当前轮次尚在执行时记录等待提示，不自动打断编码 Agent。

历史有缺页、游标失效或 Provider 无法恢复历史时，显示“总结不完整”，不宣称全量完成，不自动改名。模型未配置、超时、返回无效内容或用户取消时，保留原标题与既有成功摘要。任务阶段与错误持久保存在 Host，不再提供命名调试界面；slash 调用传输失败只记录固定错误日志，不泄露响应正文。

### 3.1 Workspace 共用「会话列表」

- 右侧 Explorer 原「智能命名」调试 tab 改名为「会话列表」，保持 workspace 单例；Command Center 同步改名。保留原面板标识，已有新版工作区 tab 复用同一入口。
- 数据来自宿主真实会话目录，分页读取；仅展示当前 Host 与当前 workspace 的会话，包含没有命名记录的会话，排除内部会话。默认全部，提供「全部／进行中／已归档」筛选及标题、会话 ID 搜索。
- 数量标题与全部／进行中／已归档／刷新放在同一行：标题靠左，四个按钮整体靠右，筛选紧邻刷新左侧，搜索在下一行；不显示“双击打开会话 · 轮次按用户提问统计”说明文字。
- 每行显示当前筛选结果的序号（从 1 起）、标题、会话时间、轮次、归档状态。时间取最后用户消息时间，无消息时取创建时间，按时间降序；命名写回本身不把旧会话顶到前面。
- 当前年份的时间省略年份；时间后附 `(刚刚)`、`(1m前)`、`(2h3m前)`、`(4d3h前)` 等相对时间，超过 30 天不附相对时间，跨年日期保留年份。时间显示每 30 秒更新，不因此重读历史。
- 列表轮次定义为完整可读取历史中的用户提问条数，包含正在执行的提问；与自动命名仅处理前 5 轮的计数独立，不把自动命名次数作为总轮数。历史不可用或不完整时显示「—」，不伪造为 0。
- 轮次仅为可见行异步读取并缓存，同一 Host 的并发历史读取最多 2 个；长列表虚拟渲染，不为统计轮次调用模型。刷新可重新尝试失败的统计。
- 单击选中，双击打开对应 Host 的原生会话；提供独立「打开会话」图标，支持移动端和键盘。打开已归档会话遵循宿主导航行为，不擅自恢复、发送消息或启动模型。
- 「更多」下拉菜单中的「智能生成标题」静默启动该会话智能命名，不新开调试页；运行中的会话禁用，已归档会话可命名。查看、筛选或打开列表本身不触发智能命名。
- 命名菜单项在实际后台任务结束前显示旋转进度及「总结对话／生成标题」，禁止重复触发；重新打开列表可恢复运行状态。成功后刷新标题，失败保留原标题并允许重试。会话行中的「总结对话／生成标题」提示放在时间、轮次和状态行下方，与标题左对齐，避免占用右侧操作区。
- 鼠标进入会话行时背景提亮、边框与操作图标强调，移开恢复；选中状态独立保留。移动端操作按钮始终可用，不依赖 hover。
- 标题后的三点「更多」菜单为锚定浮层下拉菜单，按「智能生成标题／复制标题／重新命名／永久删除」排列；每项前置图标，分别使用 Sparkles、Copy、Pencil、Trash2，统一尺寸与间距，支持 hover 与键盘焦点高亮，删除项红色且以分隔线区分。菜单宽度由 240 缩为 160，不撑开会话行，点击外部或 Esc 关闭；不保留独立智能命名图标。删除确认替换原菜单，在同一锚点显示宽 220 的迷你卡片，保留标题、范围说明、取消和删除按钮，不打开居中大弹窗。复制完整原标题，不触发导航或模型。人工改名也替换原菜单，在同一锚点显示宽 576 的紧凑浮层，不使用居中弹窗；「取消／保存」按钮组右对齐。浮层预填原标题，保存时校验非空、单行、最多 200 UTF-16 单元；不受 AI 标题默认 30 字限制。保存前复核工作区和原标题，取消旧命名任务并保护人工标题；失败保留输入以便重试。
- 不再展示摘要、命名原因、会话 ID 详情、逐次任务记录和调试操作。已有命名记录保留在 Host，支持后台恢复与排错。
- 「工作台视图」工作区下不再展开会话列表，移除项目及工作区的显示/隐藏会话菜单和设置中的默认显示会话开关；原生视图保持宿主行为。

### 3.2 永久删除及 Provider 原始历史

- 永久删除与归档分开。必须在弹窗确认目标标题与不可撤销的删除范围：Paseo 会话及时间线、Toolkit 摘要与搜索副本、对应 Provider 原始会话历史。项目目录、源码和其他会话保留。
- 执行中的会话禁止删除；请求必须属于当前 Host/workspace，标题变化后须刷新重新确认。原始会话标识被其他 Paseo 会话共用、未处理子会话可能被连带归档、标识不明或路径无法核实时，在删除前拒绝。
- 先停止并等待该会话命名任务，持久化删除状态阻止后台和重载恢复重新写回摘要；关闭空闲 Provider runtime 后清理原始历史，再通过同 Host CLI 删除 Paseo 记录，重新读取确认消失后清理 Toolkit 摘要。Provider 清理失败时保留 Paseo 条目并显示错误，可重试；清理已完成而 Paseo 删除失败时，重试不重复删除 Provider 历史。
- Codex 使用当前安装 CLI 的官方 app-server `thread/read` 验证身份及目录，调用 `thread/delete` 删除原始记录及 Provider 数据库条目，并清理同会话的提示历史、会话索引；全程不发起模型轮次。旧 CLI 不支持此接口时明确失败，不将归档显示成删除。
- Claude 按精确 UUID 与 cwd 核对 `projects/*/<sessionId>.jsonl`，删除该文件及同名子 Agent 历史目录，并清理对应 `history.jsonl` 提示记录。拒绝符号链接和归属不匹配的路径，不删除整个项目历史目录。
- Grok 支持本机 ACP Profile：解析 `extends: "acp"` 及已知 Grok 启动命令，依 `GROK_HOME` 定位。核对 `sessions/<cwd目录>/<native UUID>/summary.json` 的 `info.id/cwd` 后删除该会话目录、子 Agent 历史和同 UUID 工具状态目录；按 Grok 自身的删除逻辑清理 `session_search*.sqlite` 中的目标 `session_docs`，由已核实的 FTS5 删除触发器同步移除全文索引。其他会话的目录及索引保留，不调用模型，不删除云端副本。索引格式、归属或路径无法确认时，在删除前拒绝。
- 原始历史目录遵守当前 Host Provider 配置继承与 `CODEX_HOME`／`CLAUDE_CONFIG_DIR`／`GROK_HOME`。Grok 的 `grok acp`／`grok agent stdio` 本机启动配置可识别；任意其他自定义启动命令、远程文件系统 Provider 和其他 Provider 尚不支持，删除前拒绝；无原始标识时仅允许经历史核验的空会话。范围是本机所配置 Provider 的原始会话存储，不包括外部导出、备份或远端服务日志，也不承诺磁盘安全覆写。

## 4. 归档新建：立即 `/clear`，后台智能命名

### 4.1 入口和顺序

在输入框上方与「吸顶提问」同排提供四字按钮「归档新建」。会话空闲时可用，运行中禁用，不打断 Agent。

命令提交必须定位当前会话的可见输入框；后台保留会话的隐藏按钮标记、同会话隐藏副本和隐藏输入框不得参与归属判断。提交前会话切换、草稿变化或附件检查失败时，保留会话并取消待处理命名任务，提示具体原因。

1. 点击后捕获当前会话输入框，通过短 RPC 持久保存会话身份、既有标题、最后用户消息时间与后台命名任务。此步骤不读取完整历史、不调用模型、不自行归档。
2. 入队成功后立即向当前输入框写入 `/clear`，通过宿主正常发送按钮提交原生命令，不再由用户手动发送。先等待一次输入状态更新，避免提交旧草稿；不等待智能命名结果。
3. 原生 `/clear` 归档旧会话并立即切换到新会话草稿。插件不以直接调用归档 API 代替新草稿导航，也不把 `/clear` 发送到 Provider。
4. 归档事件启动后台智能命名：读取旧会话完整历史、分段总结、生成并写回标题。后台任务独立于旧会话按钮和会话列表存活；用户可以立即在新草稿继续工作。
5. 成功无需弹窗或聊天消息，摘要和各次处理记录保存在 Host 后台；模型失败、超时或写回失败只留后台记录，不撤销归档、不阻塞新会话。

### 4.2 失败、切换与恢复

- 任务意图须先持久化再提交 `/clear`；入队失败不提交。点击仅等待这次短 RPC 和输入更新，不承诺零网络延迟。
- 输入框带附件时不提交，避免宿主将 `/clear` 当普通 Agent 提问。输入框被移除、隐藏、切换到另一会话，或短 RPC 等待期间草稿被编辑时，保留用户内容并提示重试。
- 提交失败或插件在提交前卸载时，只取消匹配且尚未归档的命名意图，不取消已经进入后台执行的归档命名。
- 新草稿出现后，旧按钮移除不会取消后台任务。归档事件去重，重复点击只复用同一待处理任务；命名与标题写回均只作用于旧会话。
- 插件重载保留已归档任务；客户端再次连接时核对真实归档状态、原标题及最后用户消息时间后恢复，不重复归档或自动重新提交 `/clear`。无客户端连接及 SDK 上下文时，保留意图等待连接恢复。
- 已归档会话被恢复、人工改名或内容发生变化时，停止旧结果写回。
- 当前 SDK 没有公开的输入框写入与原生命令执行接口。网页和桌面使用现有输入桥接及正常发送按钮；无法定位、发送按钮不可用或原生移动端时明确提示手动使用 `/session-title` 和 `/clear`，不声称已执行。

### 4.3 与原生 `/clear` 的关系

Paseo 的 `/clear`（别名 `/new`）负责归档当前 Agent 并打开新会话草稿。本插件不注册同名命令、不拦截原生实现；「归档新建」通过当前输入框提交它。直接手动使用 `/clear` 保持宿主既有行为，不隐式新增命名任务。

## 5. 配置、状态与实现路径

| 配置         | 建议默认值   | 说明                                                   |
| ------------ | ------------ | ------------------------------------------------------ |
| 自动命名     | 开启         | 在早期轮次自动应用有效标题，可手动关闭                       |
| 自动判断轮数 | 5            | 1–20；第 1 轮包含在内                                  |
| 标题长度上限 | 30           | 1–100 个用户可见字符，同时遵守宿主 200 UTF-16 单元限制 |
| AI 模型      | 复用 Toolkit | 工作区覆盖优先，否则 Host 默认                         |

服务端在会话所在 Host 运行，客户端仅提供命令、设置与结果界面；移动端使用跨平台组件。自动命名不依赖客户端保持在线；「归档新建」的命令提交依赖客户端；智能命名在服务端执行。配置 Host 的工作台开关不隐式控制其他 Host 的命名服务。

建议模块：`server/session-title/` 负责事件处理、历史读取、分析、写回与状态；`shared/session-title/` 定义设置和 RPC；`client/session-title/` 提供静默命令及工作区会话列表。复用现有 `server/models/storage.ts`、`server/models/chat-client.ts` 和修订版 JSON 存储，不改造无关模块。

使用 `agent.turn_ended`，仅接受 `outcome.kind === "completed"` 后进入轮次判定；事件的 `timeline` 已弃用且为空，通过 `timeline.refetch` 分页读取。事件 `turnId` 可能为空或重复，使用会话身份、历史 epoch 与消息位置等建立去重依据。持久化轮次、处理位置、摘要覆盖边界、最近自动标题与人工保护状态，不能仅存在内存。

当前 0.13.x 公共插件 `PaseoApi` 缺少会话改名方法。首期可封装 CLI `paseo agent update <id> --name <title>`：以参数数组调用，显式定位同一 daemon，验证 CLI 可执行路径、连接与结果，不通过 shell 拼接标题。此路径是部署依赖，须在目标 Host 验证；若不可用，再讨论为公共 SDK 增加改名方法。禁止直接编辑 Paseo 会话内部状态文件。

同一会话任务串行处理；手动命名摘要优先于尚未落地的自动结果，同一按钮在任务入队和原生命令提交期间禁止重复触发。新轮次、人工改名或历史替换后，过期任务不得覆盖最新状态。模型失败不影响正常聊天，后台自动任务的失败不会在后续轮次突破分析窗口补跑。

状态与摘要保存到会话所在 Host 的 `$PASEO_HOME/toolkit/session-title/<agent-id-hash>.json`，使用 Host 本地存储实现跨 Host 隔离，原子写入并限制权限为 `0600`。配置页说明会话文本将发送到所选模型端点；凭据保留在既有模型存储，不写日志，不复制到客户端。不额外复制原始全量历史，保存各次摘要、任务状态、归档意图及覆盖元数据。

应用前重新读取标题与历史指纹，排除模型请求期间产生的过期结果；已应用的建议不会重复写回。当前 CLI 更新接口不支持条件写入，最后一次核对与实际写回之间仍有并发窗口；完全原子地防止人工改名冲突，需要宿主提供条件更新接口。

## 6. 验收标准

1. 首轮正常完成生成业务标题；第 2～5 轮能区分换题与同一目标的细化；第 6 轮后无自动模型调用。
2. 工具调用、权限问答、失败重试与续跑不重复计轮；重载和重新打开会话不重置轮数；重复事件不重复改名。
3. 中文、英文、组合字符及 emoji 的长度校验一致；超长或不合法输出不会覆盖原标题。
4. 人工改名及模型请求期间的标题变化得到保护；过期任务不覆盖新结果。
5. `/session-title` 对长会话使用有界命名素材，优先用户问题且保留开头、中间和近期线索，后台一次推理生成摘要并自动设置标题；摘要如有采样或裁剪须标注。不打开面板、不要求二次确认；缺失历史记录错误，不改名。
6. 未配置模型、超时、取消、无效 JSON 与历史读取失败均保留原标题及既有成功结果，并给出可理解的状态。
7. 不注册同名 `/clear` 或覆盖宿主逻辑；「归档新建」必须通过原生命令完成归档和新草稿切换。
8. 「归档新建」先可靠入队，再立即自动提交 `/clear`；模型阻塞或失败不影响新草稿出现。归档后任务继续执行，重载可恢复，重复事件不重复推理。
9. 有附件、输入框变化或入队失败时不提交；失败只取消匹配且尚未归档的意图，不能误取消后台任务。跨 workspace 列表不混淆，历史记录可切换查看。
10. 会话列表包含未命名、未曾命名与已归档会话，状态筛选和搜索正确；最近用户活动排序、超 5 轮统计、未知轮次、双击与图标打开、行尾命名、多 Host 隔离及深浅主题均可验证；左侧列表和显示/隐藏入口不再出现。
11. 筛选位于刷新左侧，无多余说明文字；今年日期省略年份、30 天以内显示相对时间。命名状态随后台阶段变化，完成或失败后解除禁用。
12. 会话行 hover 可感知；复制完整标题不打开会话。人工改名校验和并发保护生效，不调用模型；失败可重试。
13. 永久删除须独立确认，包含 Provider 原始历史；拒绝运行中、跨 workspace、共享历史、符号链接和不支持的 Provider。只在会话记录、原始历史及 Toolkit 副本均清理后报告成功，项目文件及其他会话保持完整。
