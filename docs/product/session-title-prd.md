# 会话智能命名与收尾总结 PRD

> 状态：Toolkit 首期已实现；「归档新建」改为先命名、再填入原生命令，由用户手动发送。验收边界见[验收记录](session-title-acceptance.md)。
> 日期：2026-10-26
> 主规格：[Paseo Toolkit PRD](prd.md#35-会话智能命名与收尾总结)
> 范围：自动业务命名、手动全量总结，以及 `/clear` 前的收尾总结。当前交付 Toolkit 可独立实现的命名与归档前准备能力。

## 1. 目标与边界

让会话标题准确表达业务对象、主要目标或待解决的问题，便于在会话列表与历史中识别。早期自动调整，后期保持稳定；长会话由用户主动总结并重新命名；收尾时可在切换到新草稿前保存旧会话成果。

总结、话题判断和标题生成统一复用 Toolkit 共用 AI 模型，不另建模型配置或调用当前编码 Agent。当前配置为 Host 默认模型，工作区可覆盖；沿用工作区覆盖优先、否则 Host 默认的规则。这里的“全局”指会话所在 Host 的 Toolkit 模型配置，不代表自动跨 Host 共享凭据。

摘要仅用于该会话的理解、命名与收尾，不自动加入个人记忆，也不自动发送到后续会话。首版不加入自动长期记忆、跨会话聚类或新会话上下文注入。

### 1.1 最新交互要求（2026-10-26）

- 四字入口名称统一为「智能命名」，表达会话标题自动生成；取消顶部「自动总结」按钮。
- `/session-title` 静默总结并自动设置标题，替代此前的预览、确认后应用流程。摘要与调试信息在用户主动打开面板后查看。
- 调试页按当前 workspace 只保留一个 tab，内部列出多个会话及每个会话的历次命名记录；切换查看不新增 tab。
- 「总结归档」改名为「归档新建」，仍放在「吸顶提问」旁的同一按钮行。先完成智能命名，再把 `/clear` 填入输入框，由用户手动发送；替代此前点击即归档、后台再命名的流程。
- 点击按钮不关闭或归档当前会话。用户发送 `/clear` 后，归档和新草稿均由宿主原生命令执行。

## 2. 自动命名

### 2.1 触发和轮次

| 时机               | 行为                           |
| ------------------ | ------------------------------ |
| 第 1 轮正常完成    | 总结当前目标，生成首个业务标题 |
| 第 2～5 轮正常完成 | 更新摘要，判断是否需要调整标题 |
| 第 6 轮起          | 不再自动调用模型或改名         |
| 手动总结或收尾总结 | 不受前 5 轮限制                |

一轮以用户请求及其对应的完整助手执行为单位。工具调用、进度消息、权限问答和自动续跑不单独增加产品轮次，不能直接把每个 hook 当作一轮。失败、取消不触发分析；重试正常完成后按同一请求计入。自动化消息不得伪装成用户新请求增加轮数。

轮次从会话开始累计，重载、重启、重新打开会话不重置；存量会话结合可读取历史恢复。无法可靠恢复轮次时停止自动命名，提供手动总结入口。实现前须验证各 Provider 的消息边界、重试与续跑行为。

首版默认关闭自动命名，用户启用后，前 5 轮有效结果自动应用。只对服务观察到创建的会话自动命名；存量会话统一使用手动命令。公共历史缺少完整的请求来源与失败/重试边界，多个未处理提问或历史 epoch 变化时暂停轮次自动命名，不推测轮数。新会话初始标题为空或等于 Paseo 的首行提示词临时标题时可自动命名；其余初始标题按人工标题保护。SDK 尚无标题来源字段，无法区分与临时标题完全相同的显式自定义初始标题。

### 2.2 话题变化规则

- 同一需求的细化、补充约束，以及从方案进入开发、测试，不视为换题。
- 主要业务目标变化、用户纠正此前理解，或原标题已明显不准确时，重新生成标题。
- 短暂支线、措辞变化或证据不足时保留原标题；不为了每轮都“有变化”而改名。
- 判断同时参考当前摘要、既有标题和新增对话，不能只根据最后一条消息。
- 一次模型请求返回摘要、是否改名、判断原因和推荐标题；程序校验后再写回。

自动摘要保存最新版本及历次处理记录，不在每轮聊天流中插入总结消息。手动命令发起全量总结，用户通过「智能命名」面板查看总结。

### 2.3 标题规范及人工保护

- 业务标题优先采用“业务对象＋目标/问题”，如“修复会员续费后的权益同步”。避免“继续讨论”“修改代码”等无法识别业务的标题。
- 默认最多 30 个用户可见字符，可配置为正整数，并受宿主支持的标题长度约束。中文、字母、数字、标点与空格均计入；组合字符和 emoji 不从中间拆开。
- 跟随会话主要语言，保留必要产品名、业务术语，不增加无意义引号、换行或前缀。
- 超长优先要求模型压缩一次；仍不合法则保留原标题并记录失败，不直接截断关键业务含义。
- 长度限制只约束本功能生成的标题，不裁剪用户手写标题。
- 用户手动改名后停止该会话的自动覆盖；用户显式执行 `/session-title` 时可重新生成并自动设置标题；若生成期间人工再次改名，则放弃旧结果。
- 对启用前已有的非空标题，无法确认来源时按人工标题保护；自动写回前再次核对标题，避免覆盖用户在模型请求期间的修改。

## 3. 手动命令 `/session-title`

推荐命令为 `/session-title`，含义为“后台总结当前会话并自动设置业务标题”，不是只改一个名字。注册前检查命令冲突；不使用宿主保留的 `/clear`、`/new`，也不覆盖 Provider 命令。

交互流程：

1. 固定命令触发时的历史边界，在后台开始处理；不打开面板、不弹出确认、不向聊天流插入总结。命令文本不发送给当前编码 Agent，也不增加产品轮次。
2. 分页读取截至边界的用户与助手文本，提取目标、关键决策、已完成事项、待办和话题演变。排除工具原始输出、思考过程与插件自身总结行；附件仅处理可读取的文本，不宣称理解未读取的内容。
3. 长历史按顺序分段总结，再合并摘要与生成最终标题；分段须覆盖全部可读取文本，不能以最近 N 轮采样冒充全量。
4. 成功后自动写回生成标题，并持久保存摘要、覆盖范围、原有标题和改名原因，无需再次确认。后台任务失败不弹窗，错误留在调试面板。
5. 写回前核对会话身份、历史指纹和当前标题；内容或人工标题在生成期间变化时放弃旧结果，在调试面板记录原因。当前轮次尚在执行时记录等待提示，不自动打断编码 Agent。

历史有缺页、游标失效或 Provider 无法恢复历史时，显示“总结不完整”，不宣称全量完成，不自动改名。模型未配置、超时、返回无效内容或用户取消时，保留原标题与既有成功摘要。长任务的进度与取消仅在用户主动打开调试面板时显示；slash 调用传输失败只记录固定错误日志，不泄露响应正文。

### 3.1 Workspace 共用「智能命名」面板

- 功能简称采用四字「智能命名」。移除顶部「自动总结」按钮；通过右侧 Explorer 的面板菜单或 Command Center 打开「智能命名」。
- 面板采用 workspace 上下文，同一 workspace 复用同一个 tab；切换会话、切换历史记录只更新面板内部选择，不创建新 tab。原先已打开的 Agent 上下文旧标签需关闭一次，公共 SDK 没有关闭或迁移任意旧标签的接口。
- 宽布局左侧是可搜索会话列表，右侧展示当前选择的命名记录；窄布局上下排列。列表包含已归档会话，显示记录次数、最新状态，不混入其他 workspace。
- 每次自动命名、手动命名（含「归档新建」触发）均保存独立记录；旧版总结归档记录继续保留：触发时间、来源、阶段、进度、错误、摘要、原有标题、生成标题及当次是否写回。再次生成不会覆盖以前的记录，重载后仍可查看。
- 会话 ID、覆盖边界、自动轮数和保护状态收入可折叠详情。主区域优先显示动作、状态、命名结果与摘要，不常驻显示长 ID 或重复免责声明。
- 可主动取消当前任务、重新命名，或重试已有合法但写回失败的结果。查看旧记录不触发模型和改名，关闭面板不取消后台任务。

## 4. 归档新建：先命名，再填入 `/clear`

### 4.1 入口和顺序

在输入框上方与「吸顶提问」同排提供四字按钮「归档新建」，替代旧「总结归档」。会话空闲时可用，运行中禁用；不自动打断 Agent。

1. 点击后定位并记住当前会话的输入框与草稿，启动与 `/session-title` 相同的全量智能命名；按钮在等待期间显示忙碌，阻止重复点击。
2. 等待摘要与标题生成完成，且标题成功写回。期间不归档、不关闭当前 session、不打开新草稿、不发送聊天消息。
3. 成功后向原输入框填入精确文本 `/clear` 并聚焦；只触发输入更新，不模拟 Enter，不点击发送，不调用 Agent 发送或归档接口。
4. 用户自行检查并手动发送 `/clear`；宿主内置命令随后归档旧会话并打开新会话草稿。用户可以编辑、删除命令或继续留在当前会话。

### 4.2 失败、切换与草稿保护

- 命名失败、取消、写回失败或任务被替换时，保留当前会话、原标题或既有成功结果及输入框草稿，不填入 `/clear`；错误通过按钮提示及「智能命名」记录查看。
- 等待期间用户编辑输入框，保留用户的新草稿；命名成功也不覆盖，提示用户自行输入 `/clear`。
- 只操作点击按钮时捕获的输入框；输入框被移除、隐藏或被另一会话复用时，不向其他面板填入命令。插件卸载或该会话按钮移除后停止客户端等待和填充，不自动归档。
- 当前公开 SDK 没有输入框草稿写入接口。网页和桌面复用现有输入桥接；原生移动端或无法定位输入框时明确提示先用 `/session-title` 命名，再手动输入 `/clear`，不宣称已经填入。
- 新交互不创建自动归档任务。旧版本已持久保存的归档后命名任务与历史记录仍兼容保留；恢复它们不会再次归档。

### 4.3 与原生 `/clear` 的关系

Paseo 的 `/clear`（别名 `/new`）是宿主内置命令，会归档当前 Agent 并打开新会话草稿。本插件不覆盖或自动执行该命令；仅在命名成功后准备输入文本。用户的手动发送动作才触发原生流程。

## 5. 配置、状态与实现路径

| 配置         | 建议默认值   | 说明                                                   |
| ------------ | ------------ | ------------------------------------------------------ |
| 自动命名     | 关闭         | 开启后在早期轮次自动应用有效标题                       |
| 自动判断轮数 | 5            | 1–20；第 1 轮包含在内                                  |
| 标题长度上限 | 30           | 1–100 个用户可见字符，同时遵守宿主 200 UTF-16 单元限制 |
| AI 模型      | 复用 Toolkit | 工作区覆盖优先，否则 Host 默认                         |

服务端在会话所在 Host 运行，客户端仅提供命令、设置与结果界面；移动端使用跨平台组件。自动命名不依赖客户端保持在线；「归档新建」的等待及输入框填充依赖客户端；智能命名在服务端执行。配置 Host 的工作台开关不隐式控制其他 Host 的命名服务。

建议模块：`server/session-title/` 负责事件处理、历史读取、分析、写回与状态；`shared/session-title/` 定义设置和 RPC；`client/session-title/` 提供静默命令及调试面板。复用现有 `server/models/storage.ts`、`server/models/chat-client.ts` 和修订版 JSON 存储，不改造无关模块。

使用 `agent.turn_ended`，仅接受 `outcome.kind === "completed"` 后进入轮次判定；事件的 `timeline` 已弃用且为空，通过 `timeline.refetch` 分页读取。事件 `turnId` 可能为空或重复，使用会话身份、历史 epoch 与消息位置等建立去重依据。持久化轮次、处理位置、摘要覆盖边界、最近自动标题与人工保护状态，不能仅存在内存。

当前 0.13.x 公共插件 `PaseoApi` 缺少会话改名方法。首期可封装 CLI `paseo agent update <id> --name <title>`：以参数数组调用，显式定位同一 daemon，验证 CLI 可执行路径、连接与结果，不通过 shell 拼接标题。此路径是部署依赖，须在目标 Host 验证；若不可用，再讨论为公共 SDK 增加改名方法。禁止直接编辑 Paseo 会话内部状态文件。

同一会话任务串行处理；手动全量总结优先于尚未落地的自动结果，同一按钮在命名等待期间禁止重复触发。新轮次、人工改名或历史替换后，过期任务不得覆盖最新状态。模型失败不影响正常聊天，后台自动任务的失败不会在后续轮次突破分析窗口补跑。

状态与摘要保存到会话所在 Host 的 `$PASEO_HOME/toolkit/session-title/<agent-id-hash>.json`，使用 Host 本地存储实现跨 Host 隔离，原子写入并限制权限为 `0600`。配置页说明会话文本将发送到所选模型端点；凭据保留在既有模型存储，不写日志，不复制到客户端。不额外复制原始全量历史，保存各次摘要、任务状态、归档意图及覆盖元数据。

应用前重新读取标题与历史指纹，排除模型请求期间产生的过期结果；已应用的建议不会重复写回。当前 CLI 更新接口不支持条件写入，最后一次核对与实际写回之间仍有并发窗口；完全原子地防止人工改名冲突，需要宿主提供条件更新接口。

## 6. 验收标准

1. 首轮正常完成生成业务标题；第 2～5 轮能区分换题与同一目标的细化；第 6 轮后无自动模型调用。
2. 工具调用、权限问答、失败重试与续跑不重复计轮；重载和重新打开会话不重置轮数；重复事件不重复改名。
3. 中文、英文、组合字符及 emoji 的长度校验一致；超长或不合法输出不会覆盖原标题。
4. 人工改名及模型请求期间的标题变化得到保护；过期任务不覆盖新结果。
5. `/session-title` 对超过模型单次上下文的会话执行分段覆盖，在后台生成摘要并自动设置标题；不打开面板、不要求二次确认；缺失历史记录错误，不改名。
6. 未配置模型、超时、取消、无效 JSON 与历史读取失败均保留原标题及既有成功结果，并给出可理解的状态。
7. 未支持宿主集成时不注册同名 `/clear`、不拦截输入，也不宣称已支持单命令收尾。
8. 「归档新建」先完成命名和写回，再只填入 `/clear`；按钮点击与命名期间不调用归档或发送。失败、取消、输入框变化或卸载后不填入命令，用户草稿受到保护。
9. 用户手动发送 `/clear` 后使用原生归档与新草稿流程；跨 workspace 列表不混淆，历史记录可切换查看。
10. 桌面、Web、原生移动端验证静默命令、workspace 单例面板、会话搜索、历史记录、进度、取消与深浅主题；多 Host 不串用模型、历史或标题写回目标。

## 7. 依据与待验证项

- [官方插件生命周期](https://paseo.sh/docs/plugins/reference.md#lifecycle-hooks)：轮次结果、历史读取及归档事件。
- [官方 slash 命令](https://paseo.sh/docs/plugins/reference.md#slash-commands)：内置命令优先、命令不发给 Agent、需自建任务等待界面。
- [官方 CLI](https://paseo.sh/docs/cli.md)：Host 定位与 Agent 更新命令。
- 本地 Paseo 源码核对：`packages/app/src/client-slash-commands/index.ts` 定义 `/clear` 与 `/new` 的归档并打开草稿行为；`packages/app/src/plugins/client-slash-commands/model.ts` 定义命令优先级；`packages/client/src/index.ts` 与 `daemon-client.ts` 用于核对公共 SDK 与底层改名能力差异。

开发前验证目标 daemon 与客户端版本、CLI 路径和同 Host 连接、Provider 产品轮次映射。宿主扩展、默认策略的调整以及跨 Host 统一模型配置不在本次文档更新中实现。
