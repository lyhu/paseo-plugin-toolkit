# 会话智能命名首期验收记录

日期：2026-10-26。规格：[会话智能命名与收尾总结 PRD](session-title-prd.md)。

## 交付内容

- 设置 → Toolkit → 会话智能命名：默认关闭自动命名，默认分析前 5 轮，标题最多 30 个可见字符；轮数和长度可配置。
- 新会话正常完成后的自动摘要、话题变化判断与标题维护；存量、人工标题、无法确认轮次的会话保守跳过。
- `/session-title` 全量读取用户和助手历史，分段生成累计摘要并静默自动设置标题，不打开面板、不要求确认。
- 移除顶部旧入口，右侧 workspace 共用「智能命名」tab 可搜索和切换会话、查看逐次持久记录；宽布局左右分栏，窄布局上下排列，长元数据收进详情。
- 输入框上方的「总结归档」已改为「归档新建」：先完成智能命名和标题写回，再向当前输入框填入 `/clear`；用户自行发送，按钮不直接归档或关闭 session。
- 复用既有 Toolkit Host 默认及工作区覆盖模型；摘要和状态权限 `0600`，不在客户端暴露凭据。

## 复验方法

1. 在“Toolkit 模型”确认此 Host 默认或工作区覆盖模型可用。
2. 用 `TOOLKIT_TITLE_LIVE=1 npx vitest run server/session-title/live.test.ts` 复验真实推理。测试仅发送合成文本，可能产生所配置服务的推理费用；常规测试默认不运行。
3. 在一段空闲会话中执行 `/session-title`，确认后台自动设置标题且不打开面板；通过右侧面板菜单或 Command Center 打开「智能命名」，在 workspace 会话列表中查看摘要、历史和执行状态；期间新增消息或手动改名后，旧结果必须拒绝写回。
4. 若需要自动命名，在设置中启用，再创建新的普通会话；验证第 1 轮命名、相同业务目标的细化保持稳定、主要目标变化后调整，超过配置轮数停止。
5. 空闲会话点击「归档新建」，确认当前 session 保持打开，等待命名和写回成功后，输入框出现 `/clear` 且没有自动发送。用户手动发送后，才由原生流程归档并打开新草稿；命名失败、取消、期间编辑草稿或切换会话时，不覆盖输入框。
6. 关闭一次原先已经打开的 Agent 上下文旧调试标签；通过新版 workspace 入口打开后，切换会话与记录只使用同一 tab。
7. 在网页或桌面验证当前会话输入框填充和聚焦；原生移动端缺少输入接口，应明确提示手动输入，不宣称已填入。

结论：Toolkit 首期代码、自动化回归与实际 daemon 写回已验证；真实模型成功、桌面视觉和原生移动端尚未完成验收。「归档新建」已改为准备 `/clear`，原生命令由用户手动发送；视觉/真机验收边界保留，不宣称整体全部验收通过。

## 本轮补充验证

- 覆盖归档先于推理完成、归档事件不中断、插件重载恢复、模型失败保持归档、确认丢失后的只读核对、离线时保留意图、重复点击去重及历史跨 workspace 隔离。
- 本地 pro 的实际 daemon 验证了归档 RPC、归档后标题写回与 workspace 记录列表，测试仅操作无提示词空会话。

## 「归档新建」交互修订

- 最新要求替代点击即归档流程：先完成命名和写回，再填入 `/clear`，由用户手动发送。
- 针对性测试确认等待写回、失败/取消不填入、保护等待期间编辑的草稿、任务被替换不填入、按钮移除后停止等待。
- DOM 交互测试确认只定位当前会话输入框、仅派发 `input` 事件、没有 `keydown` 或 `submit`；会话切换或输入框移除时拒绝写入。
- 上表真实 daemon 归档测试和“本轮补充验证”记录的是旧版后台能力，不作为新版按钮直接归档的验收要求。新版真实桌面点按与用户手动发送 `/clear` 仍待视觉复验。
