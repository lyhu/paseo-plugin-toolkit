## 交付内容

- 设置 → Toolkit → 会话智能命名：默认关闭自动命名，默认分析前 5 轮，标题最多 30 个可见字符；轮数和长度可配置。
- 新会话正常完成后的自动摘要、话题变化判断与标题维护；存量、人工标题、无法确认轮次的会话保守跳过。
- `/session-title` 全量读取用户和助手历史，分段生成累计摘要并静默自动设置标题，不打开面板、不要求确认。
- 移除顶部旧入口，右侧 workspace 共用「智能命名」tab 可搜索和切换会话、查看逐次持久记录；宽布局左右分栏，窄布局上下排列，长元数据收进详情。
- 输入框上方的「总结归档」已改为「归档新建」：先可靠保存后台命名任务，立即提交原生 `/clear`，宿主归档旧会话并打开新草稿；模型推理和改名异步继续，前台不等待。
- 复用既有 Toolkit Host 默认及工作区覆盖模型；摘要和状态权限 `0600`，不在客户端暴露凭据。

## 复验方法

1. 在“Toolkit 模型”确认此 Host 默认或工作区覆盖模型可用。
2. 用 `TOOLKIT_TITLE_LIVE=1 npx vitest run server/session-title/live.test.ts` 复验真实推理。测试仅发送合成文本，可能产生所配置服务的推理费用；常规测试默认不运行。
3. 在一段空闲会话中执行 `/session-title`，确认后台自动设置标题且不打开面板；通过右侧面板菜单或 Command Center 打开「智能命名」，在 workspace 会话列表中查看摘要、历史和执行状态；期间新增消息或手动改名后，旧结果必须拒绝写回。
4. 若需要自动命名，在设置中启用，再创建新的普通会话；验证第 1 轮命名、相同业务目标的细化保持稳定、主要目标变化后调整，超过配置轮数停止。
5. 空闲会话点击「归档新建」，确认无需等待模型或手动发送，原生 `/clear` 立即归档旧会话并切换到新草稿。故意让模型变慢或报错，新会话交互仍可继续，后台结果仅出现在「智能命名」记录。输入框有附件、入队失败或短 RPC 期间草稿变化时，不提交命令。
6. 关闭一次原先已经打开的 Agent 上下文旧调试标签；通过新版 workspace 入口打开后，切换会话与记录只使用同一 tab。
7. 在网页或桌面验证命令通过当前会话发送按钮提交，遵循原生归档新建流程；移动端缺少输入接口时明确提示手动操作，不宣称已执行。

结论：Toolkit 首期代码、自动化回归与实际 daemon 写回已验证；真实模型成功、桌面视觉和原生移动端尚未完成验收。「归档新建」已改为立即自动提交原生 `/clear`，后台独立命名；视觉/真机验收边界保留，不宣称整体全部验收通过。

## 本轮补充验证

- 覆盖归档先于推理完成、归档事件不中断、插件重载恢复、模型失败保持归档、确认丢失后的只读核对、离线时保留意图、重复点击去重及历史跨 workspace 隔离。
- 本地 pro 的实际 daemon 验证了 queue-clear RPC、原生归档事件启动后台任务、归档后标题写回与 workspace 记录列表，测试仅操作无提示词空会话。

## 「归档新建」最新交互修订

- 点击后只等待任务意图持久化的短 RPC，立即通过当前输入框提交原生 `/clear`，不等待模型，不要求用户手动发送。
- 客户端测试覆盖仅入队一次、无模型轮询、立即提交、入队失败不提交、草稿变化或卸载时不提交，以及失败只取消匹配的未归档任务。
- 输入桥接测试覆盖只定位当前会话、通过宿主发送按钮提交精确 `/clear`、带附件拒绝提交、发送按钮不可用或切换/卸载时拒绝提交；不通过 Agent API 发送斜杠命令。
- 服务端测试覆盖入队阶段不读取历史、不推理、不自行归档；原生归档事件后后台继续、慢模型不阻塞前台、重复事件去重、模型失败保持归档、插件重载恢复和标题保护。
- 实际 daemon 验证使用无提示词空会话，先调用 queue-clear RPC，再调用原生流程使用的归档操作，确认归档事件启动后台任务；未加载的空 Provider 会话返回历史读取错误，任务在模型请求前停止。实际桌面按钮到新草稿的视觉复验仍未完成。
